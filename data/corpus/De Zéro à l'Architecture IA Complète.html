1. LLM & Fenêtres de Contexte

Les LLMs (GPT-4, Claude, Gemini) sont des cerveaux statiques entraînés sur des trilliards de tokens. Mais les 500 Go de données privées de TechCorp n'en font pas partie. Pour que le LLM réponde sur TechCorp, il faut lui injecter des données dans sa mémoire à court terme : la fenêtre de contexte. ⏱ 0:40

Tokens & Limites

1 token ≈ 3/4 de mot. Les limites varient : 2k-4k (Nano/Flash) à 1M (Gemini 2.5 Pro). Mais 1M tokens ne représentent "que" 50 documents métiers denses. ⏱ 1:58

Le problème du "Bruit"

Sally a 14 pommes (rouges). Bob a 2 pommes (vertes, acides). Combien de pommes au total ? Le LLM doit ignorer le bruit (couleur, goût) pour calculer 14+2=16. Trop de contexte = perte de précision. ⏱ 3:52

Choix du modèle

Réécriture de roman entier → 1M tokens. Chatbot support rapide → Nano/Flash (faible latence). ⏱ 3:26

Quiz express

1. Pourquoi ne peut-on pas simplement copier-coller les 500 Go de TechCorp dans le prompt ?

Même avec 1M de tokens, 500 Go dépassent la limite, et le "bruit" noie l'information pertinente.

2. Embeddings & Bases Vectorielles

Pour contourner la limite de la fenêtre de contexte, on ne donne au LLM que les documents pertinents. Mais comment trouver "vacation policy" quand le document dit "staff time off guidelines" ? Une base SQL avec LIKE '%vacation%' échouera. La solution : rechercher par le sens, pas par la valeur. ⏱ 4:56

Embeddings

Un modèle d'embedding transforme le texte en vecteur (ex: 1536 nombres). "Vacation" et "Holiday" auront des coordonnées mathématiques très proches. ⏱ 5:02

Vector DB

ChromaDB, Pinecone... Elles stockent ces vecteurs et permettent une recherche par similarité cosinus en quelques millisecondes. ⏱ 26:42

Chunking & Overlap

On ne vectorise pas un livre entier. On le découpe en chunks (ex: 500 caractères). L'overlap (chevauchement de 100 chars) évite de couper une phrase en plein milieu d'une idée. ⏱ 31:02

Quiz express

1. À quoi sert le "Chunk Overlap" ?

Sans overlap, une règle importante pourrait être coupée en deux chunks inutilisables.

3. LangChain & Agents

Connecter OpenAI, ChromaDB, gérer la mémoire du chat, parser les réponses JSON... Écrire ce "glue code" à la main est un cauchemar. LangChain est la couche d'abstraction qui standardise tout cela. ⏱ 6:01

LLM vs Agent

LLM : Cerveau statique (répond au prompt). Agent : Autonomie, mémoire, et outils (Tools) pour décider comment exécuter la tâche. ⏱ 6:58

Abstraction

Changer d'ChatOpenAI à ChatAnthropic prend 1 ligne. Les Prompt Templates et Output Parsers structurent les entrées/sorties. ⏱ 14:40

LCEL (LangChain Expression Language)

Compose des chaînes avec l'opérateur pipe | : prompt | llm | parser. ⏱ 17:07

Quiz express

1. Quelle est la différence fondamentale entre un LLM et un Agent ?

L'agent peut appeler des APIs, chercher sur le web, ou requêter une base de données de manière autonome.

4. Prompt Engineering

La qualité de la sortie dépend de la qualité de l'entrée. "Quelle est la politique ?" donnera un essai générique. "Quelle est la politique de télétravail pour les employés internationaux en 3 puces ?" donnera une réponse exploitable. ⏱ 17:57

Zero-shot

Aucun exemple. On se fie aux connaissances brutes du modèle. Rapide, mais peu de contrôle sur le format. ⏱ 19:15

Few-shot

On fournit 1 à 3 exemples de paires (Question/Réponse) dans le prompt. Le LLM "apprend" le ton et le format attendu (In-context learning). ⏱ 19:46

Chain of Thought (CoT)

"Pensons étape par étape". On force le modèle à décomposer son raisonnement avant de conclure. Crucial pour les tâches logiques ou mathématiques. ⏱ 20:19

5. RAG (Retrieval Augmented Generation)

Le RAG est l'architecture qui unit tout : il permet au LLM de répondre sur des données privées, à jour, sans avoir à le ré-entraîner (fine-tuning). ⏱ 35:14

1. Retrieval

La question est transformée en embedding. Recherche sémantique dans la Vector DB pour extraire les Top-K chunks pertinents. ⏱ 35:40

2. Augmentation

Les chunks récupérés sont injectés dans le prompt (Contexte). Le LLM reçoit maintenant la "vérité terrain" de TechCorp. ⏱ 36:18

3. Generation

Le LLM synthétise une réponse en se basant uniquement sur le contexte fourni, réduisant les hallucinations. ⏱ 36:58

Simulateur : Pipeline RAG

6. LangGraph (Workflows Étatiques)

LangChain suffit pour des chaînes linéaires (A → B → C). Mais si le workflow de TechCorp nécessite des boucles, des conditions (ex: si score GDPR < 75%, refaire une recherche) et une mémoire d'état partagée, il faut LangGraph. ⏱ 41:39

Nœuds & Arêtes

Nœud = Fonction Python (ex: `search_docs`). Arête = Flux de données. Arête conditionnelle = Routeur dynamique basé sur l'état. ⏱ 43:15

StateGraph

Un dictionnaire partagé (ex: `{"docs": [], "score": 0}`) qui traverse les nœuds. Chaque nœud lit et met à jour l'état. ⏱ 44:10

7. MCP (Model Context Protocol)

L'agent TechCorp doit maintenant accéder à la base de données clients (SQL), au système de tickets (Jira), et à l'inventaire. Écrire des connecteurs API personnalisés pour chaque outil est long et rigide. MCP (créé par Anthropic) est le "port USB universel" pour les agents IA. ⏱ 48:51

API vs MCP

Une API expose des endpoints (le dev doit coder l'appel). Un Serveur MCP expose des outils auto-descriptifs. L'Agent lit la description et décide seul quand et comment l'appeler. ⏱ 49:31

Plug & Play

La communauté crée des serveurs MCP (GitHub, Slack, PostgreSQL). Vous les "branchez" à votre agent LangGraph sans écrire de code d'intégration. ⏱ 51:26

Flashcards

      
Token
Unité de base du LLM (≈ 3/4 de mot en anglais). Détermine le coût et la limite de la fenêtre de contexte.

      
Fenêtre de Contexte
Mémoire à court terme du LLM. Limitée (2k à 1M tokens). Trop de bruit dégrade le raisonnement.

      
Embeddings
Transformation du texte en vecteurs mathématiques (ex: 1536 dimensions) capturant le sens sémantique.

      
Vector DB
Base de données (Chroma, Pinecone) optimisée pour la recherche par similarité cosinus entre vecteurs.

      
Chunking & Overlap
Découpage du texte en morceaux. L'overlap (chevauchement) préserve le contexte sémantique entre les chunks.

      
LangChain
Couche d'abstraction pour orchestrer LLMs, Prompts, Mémoire et Outils sans réinventer la roue.

      
Agent
LLM doté d'autonomie, de mémoire et d'outils (Tools) pour exécuter des tâches complexes de manière dynamique.

      
Few-shot Prompting
Fournir des exemples (Q/R) dans le prompt pour guider le format et le ton de la réponse du LLM.

      
Chain of Thought (CoT)
Forcer le LLM à décomposer son raisonnement étape par étape avant de conclure. Améliore la logique.

      
RAG
Retrieval Augmented Generation : Injecter des documents pertinents (via Vector DB) dans le prompt pour ancrer la réponse et éviter les hallucinations.

      
LangGraph
Framework pour créer des workflows IA étatiques (StateGraph) avec boucles, conditions et routage dynamique.

      
MCP (Model Context Protocol)
Standard "USB" permettant aux Agents de se connecter à des outils/APIs externes via des serveurs auto-descriptifs.

      

    


    

      
Examen final

      
10 questions. Seuil 8/10 pour le certificat.

      

        
1. Pourquoi le "bruit" dans la fenêtre de contexte est-il problématique ?
L'analogie des pommes de Sally et Bob montre que l'information non pertinente distrait le modèle.

        
2. Quel est l'avantage principal d'une Base Vectorielle sur une base SQL ?
"Vacation" et "Time off" sont sémantiquement proches, mais lexicalement différents.

        
3. À quoi sert le "Chunk Overlap" ?
Un overlap de 10-20% assure la continuité des idées.

        
4. Dans LangChain, que fait l'opérateur pipe `|` (LCEL) ?
LCEL permet un enchaînement déclaratif et asynchrone des composants.

        
5. Le "Few-shot prompting" consiste à...
C'est de l'apprentissage in-context (In-context learning).

        
6. Quelle est la séquence correcte du RAG ?
On cherche (R), on injecte dans le prompt (A), puis le LLM répond (G).

        
7. Pourquoi utiliser LangGraph plutôt que LangChain pur ?
LangChain est linéaire, LangGraph est un graphe d'état (StateGraph).

        
8. Qu'est-ce que le MCP (Model Context Protocol) ?
MCP déporte la complexité d'intégration API du développeur vers l'Agent.

        
9. Dans un graphe LangGraph, qu'est-ce qu'un "Nœud" ?
Les nœuds sont les unités de calcul du workflow.

        
10. Comment le RAG réduit-il les hallucinations ?
Le LLM agit comme un synthétiseur de faits fournis, pas comme une base de connaissances.
