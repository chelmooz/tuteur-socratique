01 Introduction

Définition Le Graph Engineering est une méthode pour transformer un travail IA flou en un processus clair, découpé en étapes, vérifications et validations humaines. Au lieu de poser une seule question à un modèle et de lui faire confiance aveuglément, vous concevez un graphe de tâches où chaque étape a un rôle précis, où certaines tâches peuvent être exécutées en parallèle, et où les résultats sont systématiquement vérifiés avant d'être fusionnés en une décision finale.

Les trois piliers de l'interaction IA

Prompt Engineering

Comment poser une meilleure question via un Prompt structuré.

Context Engineering

Comment fournir de meilleures informations à l'IA, souvent via RAG.

Graph Engineering

Comment concevoir le workflow global pour qu'il ne vive plus dans un seul chat chaotique.

Le Graph Engineering transforme un Agentic workflow désordonné en un processus gérable et prédictible.

02 Le problème du chat unique

La manière la plus courante d'utiliser un LLM reste le chat : vous posez une question, le modèle répond en un seul bloc, vous avez l'impression d'avoir fait le travail.

Exemple typique

« Dois-je lancer ce produit pour les commerçants Shopify ? »

Le modèle peut donner une estimation du marché, quelques concurrents, un plan de go-to-market et une recommandation confiante.

Mais en réalité Un seul appel au modèle a décidé ce qui comptait, recherché le marché, interprété les preuves, écrit la recommandation et auto-évalué sa propre confiance. C'est beaucoup trop de responsabilité déléguée en une seule passe, favorisant les hallucinations.

03 Vocabulaire de base

Un Graph en AI Engineering est structuré autour de concepts fondamentaux :

  • des Nodes (tâches ou agents) ;
  • reliés par des Edges (dépendances et flux de contrôle) ;
  • avec un State persistant qui circule entre chaque étape.
Élément techniqueSignification & Rôle
NodeLieu d'exécution d'une fonction métier ou d'un appel LLM (ex: Planner, Critic).
EdgeLe chemin qui dicte le passage au nœud suivant (peut être conditionnel).
StateL'état global partagé. L'objet mémoire mis à jour par chaque Node (ex: StateGraph).

Exemple concret : support client

Un workflow de traitement de tickets n'est pas juste un Prompt « réponds à l'utilisateur ». Le véritable processus s'opère en plusieurs phases :

1 · Classifier (Node)

Analyse de l'intention et typologie de l'incident (billing, bug technique, churn risk).

2 · Context Retrieval (Node)

Recherche de la documentation et de l'historique utilisateur via RAG pour enrichir le Context Window.

3 · Draft Generation (Node)

Génération de la réponse brute basée strictement sur le contexte récupéré.

4 · Guardrail Validation (Edge Conditionnel)

Un vérificateur automatique (ou Human-in-the-loop) valide que la réponse ne contient pas d'hallucinations avant l'envoi.

04 Deux familles de Graphes

Static Graph (DAG)

Le chemin d'exécution est fixe (Direct Acyclic Graph). Les Edges sont déterministes.

  • Grande prévisibilité du workflow.
  • Débogage et monitoring simplifiés.
  • Parfait pour les pipelines de données ou la traduction massive (ex: Map-Reduce).

Dynamic Graph (Agentic)

L'IA décide dynamiquement du prochain Node en fonction du State. Gère les cycles et itérations.

  • Adaptabilité maximale face à l'imprévu.
  • Nécessite des garde-fous stricts pour éviter les boucles infinies.
  • Idéal pour la génération de Codebase (ex: Write → Execute → Fix errors → Repeat).

05 Quand utiliser le Graph Engineering ?

La règle d'or en AI Engineering : ne déployez pas un graphe complexe si un simple Few-Shot Prompt suffit. La complexité architecturale doit être justifiée.

Indicateurs de nécessité absolue
  • Cognitive Overload : La tâche nécessite plusieurs étapes de raisonnement qui dépassent les capacités de concentration d'une seule passe (phénomène de Lost in the middle).
  • Cost of Failure : Les erreurs en production ont un coût critique justifiant des Nodes de validation et des mécanismes Human-in-the-loop.
  • Tool Integration : Votre système doit interagir avec l'extérieur de manière asynchrone (Appels APIs, exécution de code, requêtes SQL).

06 Le pattern "Diamond"

Le schéma en diamant est le design pattern le plus robuste pour traiter des recherches ou analyses multidimensionnelles sans sacrifier la précision.

1. Fan-out Le Planner Node décompose la macro-tâche en N sous-tâches strictement indépendantes.
2. Parallel Execution Des Worker Nodes traitent ces sous-tâches simultanément (gain massif de latence).
3. Peer Review Le Skeptic Node (Critic) analyse les Outputs partiels pour identifier les failles logiques.
4. Fan-in Le Merge Node consolide le State final validé et l'expose à l'utilisateur.

07 Cas d'usage pratiques

Domaine Prompt classique (Fragile) Workflow Graphe (Robuste)

Research & Data "Fais-moi un résumé du marché IA." Query Generation → Web Search Tools → Fact-check → Merge Data
Content Creation "Rédige un article complet." Outline Plan → Critic → Draft Sections Parallel → Tone Alignment → Review

08 Maturité des workflows IA

Niveau 1 : Mega-Prompt

Tout dans une seule requête. Fragile, vulnérable au Prompt Drift, très difficile à debugger ou optimiser composant par composant.

Niveau 2 : Chaining linéaire

Des appels LLMs séquentiels via scripts (ex: LangChain basique). Mieux structuré, mais incapable de gérer les erreurs ou les rebouclages conditionnels.

Niveau 3 : State Graph

Architecture Agentic (ex: LangGraph). Un State explicite typé, des Conditional Edges, du routage intelligent et une tolérance aux pannes intégrée.

09 Anti-patterns et Pièges

State Bloat (Surcharge de l'état)

Le piège classique est de conserver l'intégralité de la conversation et des Outputs précédents dans le State courant. Résultat : vous explosez le Context Window, le modèle devient distrait (Lost in the middle), et vos coûts d'inférence s'envolent. Solution : Implémentez un State Filter pour ne passer au Node suivant que la donnée strictement nécessaire.

Over-Engineering Agentic

Ne créez pas une usine à gaz avec 8 Nodes si un modèle performant avec un bon System Prompt peut résoudre le problème d'un coup de manière fiable. Chaque Edge est un potentiel point de défaillance réseau et ajoute de la latence (Time to First Token retardé).

10 Gérer la mémoire du Graphe

L'orchestration d'un Agentic workflow nécessite deux paradigmes de mémorisation distincts :

Short-term Memory (State)

C'est le State local du run en cours. Il vit le temps de la complétion du graphe. Il maintient le fil d'exécution (variables, brouillons partiels, liste d'erreurs rencontrées). Stockage in-memory ou base de données rapide (Redis).

Long-term Memory (Semantic)

La connaissance globale du système à travers les différentes sessions. Préférences de l'utilisateur, documents d'entreprise, historique lointain. Récupérable via Vector Database et mécanismes RAG.

11 Principes d'architecture en production

  • Découplage cognitif : Séparez la logique décisionnelle (le LLM) de la logique d'exécution (votre Codebase Python/TypeScript).
  • Typage strict (Structured Output) : Le State doit toujours être validé. Forcez vos Nodes à cracher des données structurées via des schémas Pydantic ou Zod (JSON mode strict).
  • Checkpoints (Human-in-the-loop) : Marquez les Nodes exécutant des actions irréversibles (envoi d'email, modification DB, achat API) avec un point d'arrêt nécessitant une validation humaine. L'état est suspendu (AFK) en attendant l'approbation.
Graph Engineering + Typage Fort + Petits Modèles Spécialisés (SLMs) = Système Fiable en Production

12 Exercice de réflexion

Analysez votre processus IA interne le plus long (génération de rapports, analyse de code, recherche concurrentielle). Comment pourriez-vous le refactoriser selon un schéma Agentic en diamant ?

Votre défi architectural :

Identifiez explicitement : (1) Le Planner, (2) Les Workers parallèles, (3) Le Skeptic de validation, (4) La condition de Human-in-the-loop.

Engineering Tip : Assurez-vous d'utiliser une température (temperature=0) pour le Planner afin de garantir un comportement déterministe, mais autorisez une légère variance (temperature=0.3) pour le Skeptic afin de maximiser sa capacité critique face aux Workers. N'utilisez pas le même System Prompt pour le critique et le créateur !
