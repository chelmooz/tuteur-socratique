Apprendre à une machine à comprendre plusieurs modalités

Cette leçon couvre la multimodalité : ce que sont les modèles multimodaux, et surtout comment enseigner à un ordinateur la compréhension de données multimodales via le contrastive representation learning. On part du live demo de recherche multimodale (texte → images, audio, vidéo) et on finit par un lab complet : entraîner un réseau sur MNIST avec une contrastive loss, puis visualiser l espace vectoriel appris avec PCA et UMAP. ⏱ 0:01

Objectif

Comprendre comment unifier texte, image, audio et vidéo dans un même espace vectoriel, et savoir le mettre en œuvre (loss contrastive, MNIST, PCA/UMAP).

Méthode

Données multimodales et embeddings conjoints

Une donnée multimodale vient de sources différentes : texte, images, audio, vidéo, et plus. Chaque modalité décrit souvent des concepts similaires — une photo de lion, un paragraphe sur le roi de la jungle, une vidéo de lions qui courent, le son d un rugissement. Les multimodal embeddings permettent de représenter tout cela dans le même espace vectoriel. ⏱ 1:16

Espace conjoint

Contrastive representation learning : ancre, positif, négatif

Unifier plusieurs modèles dans un même espace se fait par le contrastive representation learning : un procédé général qui entraîne n importe quel modèle d embedding — et qui, ici, unifie plusieurs modèles en un seul modèle multimodal. L idée : fournir des exemples positifs (similaires) et négatifs (différents), puis tirer les vecteurs similaires et pousser les différents. ⏱ 4:09

Exemple texte

Exemple image

La contrastive loss, CLIP et ImageBind

Le push/pull s accomplit avec la contrastive loss function : encoder ancre et exemples en vecteurs de même dimension, calculer les distances, puis minimiser la distance à l ancre pour les positifs et la maximiser pour les négatifs. ⏱ 5:41

L = − log  exp( sim(q, k⁺)/τ ) / [ exp( sim(q, k⁺)/τ ) + Σj exp( sim(q, k⁻ⱼ)/τ ) ]

Fonctions d encodage

f prend une image → vecteur q ; g prend une vidéo → vecteur k. Même dimension. ⏱ 7:03

Numérateur

Similarité entre exemples positifs (image de lion + vidéo de lions qui courent) : on veut qu elle soit la plus haute possible. ⏱ 7:20

Dénominateur

Un négatif (image de lion + chatons sur un vélo) — en fait un parmi beaucoup qu il faut sommer. On normalise en remettant le positif, et le signe moins devant la loss signifie : minimiser. ⏱ 7:35

Effet

Minimiser tire les embeddings vidéo positifs vers l ancre image et pousse la vidéo négative loin. À faire modalité par modalité (audio, texte, vidéo) — c est ce que fait ImageBind. ⏱ 8:02

CLIP (2021) : la diagonale comme positif

Trouver assez d ancres et d exemples contrastés est délicat. CLIP prend des images et leurs légendes correspondantes : l image + sa légende = ancre + positif (diagonale de la matrice) ; tout autre pairing aléatoire image/légende est probablement un négatif.

Survole une cellule : verte = paire (image, sa légende) → positif ; rouge = pairing aléatoire → négatif.

Lab : entraînez un modèle d embeddings sur MNIST

On entraîne un réseau à apprendre des embeddings sur le dataset d images de chiffres MNIST (0-9), avec la contrastive loss, puis on visualise l espace appris. Imports : PyTorch, plotly, umap, et la classe MNISTDataset qui fournit ancre + positifs + négatifs. ⏱ 8:30

MNISTDataset

Chaque image de chiffre est étiquetée. La classe fournit une ancre (un chiffre), un positif (autre image du même chiffre) et un négatif (autre chiffre, ex. ancre 5 → positif 5, négatif 6 ou 7). ⏱ 9:09

Clé 1 : labeling

Si le label de l exemple correspond à celui de l ancre → positif ; sinon → négatif. ⏱ 9:54

Clé 2 : distances idéales

Avec la similarité cosinus : positif idéal = 1, négatif idéal = 0. ⏱ 10:20

Architecture

2 couches convolutives (extraire les features visuelles du chiffre) + 2 couches linéaires (transformer ces features en représentation 64-d). Image → conv → conv → flatten → lin → lin → vecteur 64-d. ⏱ 12:22

# mnist_dataset.py — les deux parties clés
# 1) labeling positif / négatif
if example_label == anchor_label:
    positives.append(example)      # 7 avec 7  -> positif
else:
    negatives.append(example)      # 7 avec 5  -> négatif

# 2) distance idéale (cosine similarity)
ideal_distance = 1.0 if is_positive else 0.0
# contrastive loss : cosinus vs distance idéale
class ContrastiveLoss(nn.Module):
    def forward(self, anchor, contrasted, ideal_distance):
        s = F.cosine_similarity(anchor, contrasted)   # étape 1 : score
        return ((s - ideal_distance) ** 2).mean()     # étape 2 : écarter de l'idéal

Anti-patterns du contrastive learning

      

        
Oublier la métrique dans UMAP
Laissé en euclidien par défaut alors que le modèle est entraîné en cosinus → clusters trompeurs (« strings »).

        
Trop peu de négatifs
Un seul négatif par ancre ≈ pas de signal ; CLIP exploite justement tous les autres pairings de la matrice.

        
Positifs triviaux
Un « positif » qui n est pas le même concept (lion vs chaton) apprend à confondre plutôt qu à aligner.

        
Comparer des vecteurs de dimensions différentes
La loss exige des encodages f/g de même dimension ; sinon la similarité n a pas de sens.

        
Relancer tout l entraînement à chaque question
Comme dans le lab RAG : ré-encoder à chaque requête est inefficace — encoder une fois, réutiliser.

        
Interpréter 3D comme la vérité
La compression 64→3 peut rapprocher visuellement des chiffres distincts (2 et 4) selon l angle.

        
τ fixe sans test
La température contrôle la netteté du contraste ; trop haute = tout flou, trop basse = gradient mort.
