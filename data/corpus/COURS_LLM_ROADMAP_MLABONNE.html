Le parcours complet pour comprendre et construire des LLM

Maxime Labonne a organisé son dépôt llm-course en trois parcours : des fondamentaux optionnels, la voie LLM Scientist pour construire les meilleurs modèles, et la voie LLM Engineer pour créer et déployer des applications autour de ces modèles. Cette page reprend cette carte et la rend explorable : cliquez une étape pour lire son détail.

Fondamentaux

optionnel

Mathématiques, Python et réseaux de neurones : une base à consulter au besoin plutôt qu'un prérequis strict avant de commencer.

1Mathématiques pour le machine learning

Les bases mathématiques qui sous-tendent les algorithmes de machine learning : l'algèbre linéaire pour manipuler vecteurs et matrices, le calcul différentiel pour l'optimisation par gradient, et les probabilités/statistiques pour comprendre comment un modèle apprend à partir de données.

Algèbre linéaireCalcul différentielProbabilités & statistiques
Ressources
  • 3Blue1Brown — The Essence of Linear Algebra
  • Khan Academy — Calculus
  • Seeing Theory
2Python pour le machine learning

Python est le langage de référence du machine learning grâce à son écosystème : manipulation des données avec NumPy et Pandas, visualisation avec Matplotlib et Seaborn, prétraitement (normalisation, valeurs manquantes, encodage) et bibliothèques comme Scikit-learn pour les algorithmes classiques.

NumPy / PandasPrétraitement des donnéesScikit-learn
Ressources
  • Real Python
  • Python Data Science Handbook
  • freeCodeCamp — Machine Learning for Everybody
3Réseaux de neurones

Les réseaux de neurones sont au cœur du deep learning : structure en couches, poids, biais et fonctions d'activation ; entraînement par rétropropagation et descente de gradient ; et gestion du surapprentissage par régularisation (dropout, L1/L2, early stopping).

RétropropagationFonctions d'activationRégularisation
Ressources
  • 3Blue1Brown — But what is a Neural Network?
  • freeCodeCamp — Deep Learning Crash Course
4Traitement du langage naturel (NLP)

Avant les LLM, le NLP posait déjà les bases : prétraitement du texte (tokenisation, lemmatisation), extraction de features (TF-IDF, n-grams), plongements lexicaux (Word2Vec, GloVe) et réseaux récurrents (RNN, LSTM, GRU) pour traiter des séquences.

TokenisationWord embeddingsRNN / LSTM
Ressources
  • Jay Alammar — The Illustrated Word2Vec
  • colah's blog — Understanding LSTM Networks

LLM Scientist

construire

De l'architecture des Transformers jusqu'aux tendances les plus récentes : tout ce qu'il faut pour entraîner, aligner et évaluer un LLM.

1L'architecture des LLM

Comprendre les grandes étapes d'un LLM moderne : la tokenisation transforme le texte en nombres, les mécanismes d'attention (self-attention) traitent les dépendances à longue portée, et différentes stratégies d'échantillonnage (greedy, beam search, nucleus sampling) génèrent le texte final.

TokenisationSelf-attentionÉchantillonnage
Ressources
  • LLM Visualization — Brendan Bycroft
  • 3Blue1Brown — Visual intro to Transformers
  • nanoGPT — Andrej Karpathy
2Pré-entraînement

Étape coûteuse en calcul : préparation de jeux de données massifs (des milliers de milliards de tokens), entraînement distribué combinant parallélisme de données, de pipeline et de tenseurs, optimisation (warm-up, mixed precision, AdamW) et suivi rigoureux des métriques d'entraînement.

Données à l'échelleEntraînement distribuéMonitoring
Ressources
  • FineWeb — Hugging Face
  • nanotron — Hugging Face
3Jeux de données de post-entraînement

Les données de post-entraînement suivent une structure conversationnelle précise (instruction/réponse, ou choisi/rejeté). Elles combinent formats de stockage (ShareGPT, ChatML), génération synthétique avec des modèles frontière, et filtrage qualité (déduplication, décontamination).

Chat templatesGénération synthétiqueFiltrage qualité
Ressources
  • LLM Datasets — Maxime Labonne
  • Chat Template — Hugging Face
4Fine-tuning supervisé (SFT)

Le SFT transforme un modèle de base en assistant utile. Le fine-tuning complet met à jour tous les paramètres ; les techniques efficaces comme LoRA et QLoRA n'entraînent qu'un petit nombre de paramètres d'adaptateurs, avec des frameworks comme TRL, Unsloth ou Axolotl.

LoRA / QLoRAHyperparamètresEntraînement distribué
Ressources
  • Fine-tune Llama 3.1 avec Unsloth — Maxime Labonne
  • Axolotl — Documentation
5Alignement sur les préférences

Deuxième étape du post-entraînement : aligner les réponses générées sur les préférences humaines. DPO optimise directement la politique sans modèle de récompense ; les techniques de RL comme GRPO et PPO sont plus coûteuses mais adaptées aux modèles de raisonnement.

DPOModèle de récompenseGRPO / PPO
Ressources
  • Illustrating RLHF — Hugging Face
  • Fine-tune avec DPO — Maxime Labonne
6Évaluation

Évaluer un LLM guide la génération de données et l'entraînement. Les benchmarks automatisés (comme MMLU) sont efficaces sur des tâches concrètes mais sensibles à la contamination ; l'évaluation humaine et les modèles juges apportent d'autres angles, chacun avec ses propres biais.

Benchmarks automatisésÉvaluation humaineModèles juges
Ressources
  • Open LLM Leaderboard — Hugging Face
  • Chatbot Arena — LMSYS
7Quantization

Réduire la précision des poids et activations (par exemple de FP16 vers INT4) diminue le coût mémoire et calcul. GGUF et llama.cpp dominent sur matériel grand public ; GPTQ, AWQ et SmoothQuant affinent la calibration pour préserver la performance à très basse précision.

GGUF / llama.cppGPTQ / AWQSmoothQuant
Ressources
  • Introduction to quantization — Maxime Labonne
  • 4-bit LLM Quantization with GPTQ — Maxime Labonne
8Nouvelles tendances

Des sujets en évolution rapide : le model merging (SLERP, DARE, TIES) crée des modèles performants sans entraînement, les modèles multimodaux unifient texte/image/audio, l'interprétabilité mécanistique éclaire le fonctionnement interne, et le test-time compute améliore le raisonnement en allouant plus de calcul à l'inférence.

Model mergingMultimodalitéTest-time compute
Ressources
  • Merge LLMs with mergekit — Maxime Labonne
  • Scaling test-time compute — Beeching et al.

LLM Engineer

déployer

De la première requête API jusqu'à la sécurisation en production : construire de vraies applications autour d'un LLM.

1Faire tourner un LLM

Selon le cas d'usage, on consomme un LLM via une API (OpenAI, Anthropic, Google) ou on le fait tourner en local via le Hugging Face Hub, LM Studio ou llama.cpp/Ollama. Le prompt engineering (zero-shot, few-shot, chain-of-thought) et le structured output affinent les résultats obtenus.

APIs vs localPrompt engineeringSorties structurées
Ressources
  • Prompt engineering guide — DAIR.AI
  • Outlines — Quickstart
2Construire un stockage vectoriel

Première étape d'un pipeline RAG : ingérer des documents (PDF, HTML, Markdown), les découper en chunks sémantiquement cohérents, les transformer en vecteurs avec un modèle d'embedding adapté à la tâche, puis les stocker dans une base vectorielle (Chroma, Pinecone, FAISS, Milvus).

ChunkingEmbeddingsBases vectorielles
Ressources
  • MTEB Leaderboard
  • Sentence Transformers
3Retrieval Augmented Generation (RAG)

Le RAG augmente les réponses d'un LLM avec des documents récupérés dans une base, sans fine-tuning. Les orchestrateurs (LangChain, LlamaIndex, MCP) connectent le modèle aux outils et données ; l'évaluation porte à la fois sur la récupération (précision, rappel) et la génération (fidélité, pertinence).

OrchestrateursRetrieversÉvaluation RAG
Ressources
  • LangChain — Q&A with RAG
  • Model Context Protocol
4RAG avancé

Pour des cas réels plus complexes : la construction de requêtes traduit une instruction en langage naturel vers SQL ou Cypher, les agents sélectionnent automatiquement des outils pertinents, le post-processing améliore la pertinence des documents récupérés (re-ranking, RAG-fusion), et des frameworks comme DSPy optimisent les prompts de façon programmatique.

Query constructionRe-rankingDSPy
Ressources
  • LangChain — Query Construction
  • DSPy in 8 Steps
5Agents

Un agent LLM agit de façon autonome en alternant réflexion, action (via des outils) et observation des résultats. Le Model Context Protocol (MCP) standardise la connexion aux outils externes ; des frameworks comme LangGraph, CrewAI ou AutoGen orchestrent des workflows mono- ou multi-agents.

Réflexion / Action / ObservationMCPMulti-agents
Ressources
  • Agents Course — Hugging Face
  • Model Context Protocol
6Optimisation de l'inférence

Générer du texte reste coûteux. Flash Attention rend le mécanisme d'attention linéaire plutôt que quadratique, le cache clé-valeur (amélioré par MQA et GQA) évite de recalculer les représentations passées, et le speculative decoding utilise un petit modèle pour accélérer un plus grand modèle.

Flash AttentionCache clé-valeurSpeculative decoding
Ressources
  • Optimizing LLMs for Speed and Memory — Hugging Face
  • Assisted Generation — Hugging Face
7Déployer des LLM

Le déploiement local préserve la confidentialité (LM Studio, Ollama, kobold.cpp) ; les démos se prototypent vite avec Gradio ou Streamlit ; le déploiement à grande échelle s'appuie sur des frameworks optimisés comme vLLM ou TGI ; et l'edge deployment fait tourner des modèles dans le navigateur ou sur mobile.

Déploiement localDémosPassage à l'échelle
Ressources
  • Streamlit — Build a basic LLM app
  • vLLM
8Sécuriser les LLM

Les LLM ont des failles propres à leur fonctionnement : le prompt hacking regroupe l'injection de prompt, la fuite de données et le jailbreak ; les backdoors empoisonnent les données d'entraînement ; la défense passe par le red teaming (garak) et l'observation en production (langfuse).

Prompt hackingBackdoorsRed teaming

  • OWASP LLM Top 10
  • LLM Security — @llm_sec
