Les Trois Âges du RAG

Comment la récupération d’information est devenue un raisonnement : Classic retrieves, Graph connects, Agentic reasons.

Un LLM seul ressemble à un candidat sans documents : sa connaissance est figée dans ses poids, il ignore les informations récentes et peut inventer. Le RAG branche une mémoire externe consultable et vérifiable.

Quiz

Que fournit principalement le RAG à un LLM ?

Âge 1 • Retrieves

Classic RAG — le bibliothécaire

Le pipeline transforme la question en vecteur, interroge une base vectorielle, récupère les top-K chunks puis demande au LLM de répondre avec ce contexte.

Question → embedding
→ Vector DB → top-K chunks (similarité cosinus)
→ prompt = question + chunks
→ réponse sourcée

Force

Rapide, simple, peu coûteux : excellent pour une question single-hop dans un document homogène.

Faiblesse

Fragile si la réponse est répartie dans plusieurs chunks ou si l’on demande une vue globale.

Âge 2 • Connects

Graph RAG — le cartographe

Le système extrait entités et relations, construit un graphe de connaissance puis récupère le voisinage ou la communauté pertinente.

Marie ──works_at──► CompanyX
CompanyX ──located_in──► Paris
Question : ville de l’employeur de Marie ?
Parcours : Marie → CompanyX → Paris (2 hops)

Local search

Voisinage d’une entité pour une question précise.

Global search

Communautés et résumés pour comprendre les thèmes du corpus.

Âge 3 • Reasons

Agentic RAG — l’enquêteur

L’agent planifie, route et combine Vector DB, Knowledge Graph, SQL, Web ou APIs. Il s’auto-évalue et recommence si la réponse est insuffisante.

Question hybride
→ planifier des sous-requêtes
→ router : SQL + Vector DB + Web
→ agréger les résultats
→ juger : sources suffisantes ?
→ re-retrieve si nécessaire → réponse finale

Force

Adaptatif, multi-hop, multi-source et auto-correctif.

Coût

Latence et tokens plus élevés, orchestration complexe et risque d’erreur cumulative du juge.

Synthèse

Choisir et combiner

Classic

Fait localisé dans un document ?
Faible latence, vector DB, single-hop.

Graph

Relations ou vue globale ?
Entités, communautés, multi-hop.

Agentic

Tâche ouverte et sources hétérogènes ?
Planification, outils, vérification.

Point clé : Agentic RAG ne remplace pas Classic ou Graph ; il les pilote comme des outils à un niveau d’organisation supérieur.
