Le Guide de l'Agent Harness Engineering

Inspiré de la vidéo de Shaw Talebi. Découvrez comment construire l'environnement qui rend l'IA réellement utile et autonome.

1. Introduction : Qu'est-ce qu'un « Harness » ?

Définition : Un agent harness regroupe tout ce qui est construit autour d'un modèle d'IA pour le rendre plus utile et performant.

L'Analogie de la Voiture

Pour bien comprendre, faisons un parallèle avec l'automobile :

  • Le Modèle d'IA = Le moteur de la voiture.
  • L'Agent Harness = Tout le reste (les roues, la carrosserie, les sièges, le volant, le tableau de bord).

De même que l'on personnalise une voiture pour l'adapter à ses besoins, on personnalise l'agent harness pour optimiser les performances de l'IA.

2. Les 3 Niveaux de Harness Engineering

La classification des niveaux dépend de votre point de départ et de votre expertise technique.

01

Clé en main
(Off-the-shelf)

Exemples : Claude Co-work, ChatGPT Work.

Analogie : Acheter une voiture de série. On peut ajuster les sièges ou la couleur, mais on ne change pas le moteur.

02

Tuning Avancé

Exemples : Claude Code.

Analogie : Préparer une voiture pour la F1. On optimise chaque détail pour aller plus vite, ce qui demande une expertise pointue.

03

Sur-mesure
(Custom Agent Harness)

Approche : Utilisation directe d'API et écriture de code personnalisé autour de son modèle favori.

Analogie : Construire son propre véhicule à partir d'un moteur brut. Liberté totale, complexité maximale.

3. Les 3 Leviers d'Optimisation

Pour piloter et optimiser votre harness (du niveau 1 au niveau 2), vous disposez de trois leviers principaux. Cliquez pour explorer :

Levier 1 : Le Contexte (Context)

Le contexte englobe les instructions, les connaissances et les données mises à disposition de l'agent.

  • Contexte natif : Instructions système, métadonnées (date, lieu), et memories (mémoires extraites des conversations passées).
  • Personnalisation par fichier : Fichier de configuration global (ex. claude.md) injecté automatiquement au début de chaque session.
  • Le concept des Skills : Un dossier contenant un fichier central skill.md (prompt sophistiqué), des références, templates ou scripts Python.
  • Progressive Disclosure : Pour ne pas surcharger la fenêtre de contexte, l'IA ne charge initialement que la liste des skills, et n'importe le contenu détaillé que lorsqu'il devient pertinent.
  • Sources externes : Connexion à Notion, Obsidian, Confluence, Google Drive, évitant de saturer le contexte local.

Levier 2 : Les Outils (Tools)

Les outils permettent à l'agent d'interagir activement avec des applications et services externes (en lecture comme en écriture).

  • Outils natifs : Web Search, Code Interpreter.
  • Connecteurs et serveurs MCP (Model Context Protocol) : Relient l'IA à des environnements professionnels (Gmail, Slack, HubSpot, Jira, Canva, etc.).
  • Outils via les Skills : Intégration de scripts en ligne de commande ou d'appels API (piloter Keynote, éditer des vidéos Final Cut Pro, interagir avec Railway, YouTube Analytics, ConvertKit ou MUX).

Levier 3 : Les Automations (Automations)

Processus s'exécutant automatiquement, déclenchés par le temps ou par des événements spécifiques.

  • Automations natives : Filtrage anti-prompt injection, prétraitement des PDF, modération.
  • Planification de tâches (Scheduled Tasks) : Exécution récurrente (ex. commande /schedule pour une préparation de réunion matinale).
  • Les Hooks : Déclenchés par des événements précis (dans Claude Code ou Cursor) :
    • Sauvegarder et pousser automatiquement la config sur GitHub à la fermeture d'une session.
    • Nettoyer les captures d'écran générées par un outil comme Playwright MCP.
    • Déclencher un contrôle qualité via Git avant un push.

4. Le Levier Bonus : Les Evals

Définition : Les evals sont des tests automatisés qui indiquent à l'agent si son travail est correct ou non.

Sans Evals (Human-in-the-loop)

Humain envoie requête → Agent génère → Humain évalue → Humain corrige. Répétition lente.

Avec Evals (Agent-in-the-loop)

Agent génère → Exécute tests d'évaluation → S'auto-corrige en boucle → Présente le résultat final. Autonomie et vitesse.

Cas d'étude : Le projet Auto-Research d'Andrei Karpathy

Au lieu d'écrire et d'itérer manuellement sur ses scripts d'entraînement de machine learning (train.py), Karpathy a écrit un fichier de programme (program.md) guidant l'agent. Le système a tourné toute la nuit, évaluant et optimisant les hyperparamètres de manière autonome pour surpasser les performances initiales de son créateur.

5. Conclusion & Mindset : L'Agent Empathy

Pour réussir en tant que Harness Engineer, il faut opérer un changement fondamental de mentalité :

Ancien réflexe : « Comment est-ce que je fais cette tâche ? »
Nouveau réflexe : « Comment est-ce que je construis le harness pour que l'IA réalise cette tâche de façon fiable ? »

Agent Empathy (Empathie envers l'agent)

Mettez-vous à la place de l'agent. Face au contexte fourni et aux outils à disposition, seriez-vous capable de réussir la tâche ? Si la réponse est non, demandez-vous comment améliorer le harness pour l'aider à réussir.
