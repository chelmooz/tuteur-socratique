Définition : qu'est-ce qu'un local AI agent ?

Un agent IA est une IA qui peut prendre des actions et compléter des tâches seule. Ce qui devient excitant, c'est qu'il est local : il vit et tourne sur votre machine personnelle. ⏱ 1:19

Agent IA

Pas seulement répondre. Il agit, appelle des outils, lit, écrit, exécute, planifie, itère.

Local

Sur laptop, vieux laptop, Mac Mini, Mac Studio, PC ou VPS. Vos données peuvent rester chez vous.

Exemples du transcript

  • Morning brief personnalisé : calendrier, emails, priorités, portfolio, notes, news.
  • Recherche continue pour améliorer un business.
  • Construction autonome de logiciels : finance tracker, accounting, dashboard étudiants, trading bots.
  • Interaction distante depuis le téléphone.

Machine : où vit votre agent ?

        
Un agent local peut vivre sur laptop personnel, vieux laptop wipe, Mac Mini, Mac Studio, PC ou VPS. Trois facteurs décident du bon hébergement. ⏱ 2:35

        

          
1. 24/7
Si vous voulez un agent continuellement actif, un laptop que vous transportez ne suffit pas. Il faut une machine always-on. ⏱ 3:00

          
2. Specs
CPU, GPU, mais surtout RAM. Les gros modèles open-source exigent une machine capable de les porter. ⏱ 3:10

          
3. Privacy / security
À quel point êtes-vous paranoïaque ? Des agents mal gardés sur machine personnelle ont pu supprimer des emails ou accéder à trop de choses. ⏱ 3:31

        

        
Setup du transcript
Le créateur commence avec un vieux MacBook Pro wipe, 16 GB RAM, 24/7, dédié. Comme la RAM est limitée, il utilise Claude Sonnet/Opus plutôt que gros modèles open-source. Puis il passe à Mac Mini, Mac Studio, et d'autres machines dédiées. ⏱ 4:04

        
Conseil pratique
Le transcript propose un prompt à coller dans Claude ou ChatGPT pour vous aider à choisir l'option d'hébergement selon votre hardware. Hosting et hardware sont de vrais blockers pour beaucoup. ⏱ 4:51

Communication : bouche et oreilles

        
Il faut donner à Inky un canal pour que vous puissiez lui parler et qu'il vous réponde. C'est aussi ce qui permet l'interaction distante depuis le téléphone. ⏱ 5:15

        

          
Facile
Single-channel messaging. Telegram est souvent l'option de départ. Dispatch si vous êtes dans l'écosystème Claude. ⏱ 5:38

          
Avancé
Discord avec plusieurs channels pour organiser projets, alertes, pipelines de contenu, logs. ⏱ 5:46

          
Options
WhatsApp, iMessage, Slack, Telegram, Discord, Dispatch. Beaucoup sont déjà familiers. ⏱ 5:28

        

        

      


      

        
Cerveau et mémoire

        
Le cerveau est le LLM. La mémoire est un ensemble de fichiers texte qui documentent qui est l'agent, ce qu'il fait, ce qu'il sait de vous, et ce qu'il a appris. ⏱ 6:06

        

          
Cloud models
Claude Opus, Claude Sonnet, OpenAI. Souvent plus capables, mais payants et hors machine.

          
Open source
Qwen, Kimi, Ministral, DeepSeek. Trade-offs : capabilities, size, speed, cost, privacy. ⏱ 6:13

          
Popularité
Selon le transcript, les options les plus populaires pour agents locaux sont Claude Opus/Sonnet, et côté open-source Qwen/Kimi. ⏱ 6:33

          
Mémoire
Littéralement des fichiers texte : personnalité, workflows, données, infos utilisateur, logs de tâches. La plupart des frameworks ont une mémoire pré-construite. Les power users renforcent avec Obsidian. ⏱ 6:48

        

        
Exemple de contenu mémoire :
- Qui est Inky ?
- Personality type
- Workflows attendus
- Données accessibles
- Qui est l'utilisateur ?
- Job, démographie, préférences
- Ce que l'agent a fait récemment

Tools, Heartbeat, Eyes

        

          
Tentacules = skills/tools
Inky vient avec des tentacules pré-construites : chercher dans les fichiers, exécuter du code. Vous pouvez ajouter web search, email, screenshots, text to speech, image generation, etc. ⏱ 7:45

          
Heartbeat
Permet de scheduler des tâches sans demande explicite : toutes les 30 minutes scanner email, chaque mois rendez-vous médecin, chaque matin 7h morning brief, ou à chaque fichier ajouté dans un dossier comptabilité. ⏱ 8:14

          
Eyes
Computer use : voir ce qui se passe sur l'ordinateur, interagir comme un humain, bouger la souris, voir l'écran, faire des choses à votre place. ⏱ 8:47

        

        
Game changers
Le transcript met l'accent sur le heartbeat et les workflows schedulés. C'est ce qui transforme un chatbot réactif en système autonome. ⏱ 8:41

Multi-agents : équipes et tâches parallèles

        
Une fois Inky conçu, il n'y a aucune raison d'en avoir un seul. Vous pouvez avoir plusieurs agents faisant plusieurs tâches en parallèle, ou des équipes où chaque agent a une fonction spécifique. ⏱ 9:32

        

          
Research team
Exemple du transcript : une équipe qui regarde des stocks potentiels.

          
Software team
Une équipe qui recherche, prend des décisions produit et construit des logiciels pour la company.

          
Parallélisme
Un agent fait de la recherche, un autre gère le calendrier, un autre écrit une campagne marketing. Le tout simultanément.

          
Principe
Ensemble, ils produisent quelque chose de supérieur à la somme des parties. Mais multi-agent introduit de la complexité de design. ⏱ 9:46

        

        

      


      

        
Sécurité et good engineering

        
Safety est la préoccupation primaire : vous donnez à un agent intelligent l'accès à votre computer. Il faut éviter qu'il devienne bananas. ⏱ 11:56

        

          
Isoler
Ne pas tourner sur la machine principale contenant toutes vos données. Utiliser des machines dédiées sans informations sensibles. ⏱ 12:24

          
Limiter l'accès
Donner accès à certaines emails de screening, pas aux emails personnels sensibles. Créer des boîtes dédiées. ⏱ 12:37

          
Méfier des skills tiers
Les workflows partagés peuvent contenir des choses malveillantes. Ne pas installer sans confiance forte. ⏱ 12:51

          
Scanner et réécrire
Si une skill semble utile, la donner à Claude pour scan et rewrite, puis seulement la donner à l'agent local. ⏱ 13:13

          
Audit automatique
Utiliser le heartbeat pour lancer un security audit toutes les heures ou minimalement chaque jour. ⏱ 13:33

          
Engineering
Toujours donner des instructions claires. Ajouter une feature ou un workflow à la fois. Ne pas demander cinq choses en même temps. ⏱ 13:48

Démo Claude Cowork : no-code plus safe

        
Claude Cowork est présenté comme l'option Anthropic, plus sûre et plus facile pour les non-techniques. Contrepartie : moins de customisation et lock-in à l'écosystème Anthropic. ⏱ 20:05

        

          
Folder-based
Cowork vit sur votre computer et correspond à un folder. Projects séparés : content studio, portfolio, personal, etc. ⏱ 20:49

          
Memory files
CLAUDE.md et memory.md, lisibles via Obsidian. Informations sur l'utilisateur, coworkplace, mémoire système. ⏱ 21:02

          
Portfolio dashboard
Questions sur investissement : top winner, biggest loser. Claude Code peut construire un investments dashboard qui se met à jour : positions, research segments, watch list. ⏱ 21:26

          
Skills / connectors / plugins
Connexion Google Drive, Google Calendar, Gmail, Microsoft 365. Plugins = combinaisons de skills et connectors pour un purpose, par exemple finance. ⏱ 22:20

          
Scheduled tasks
Heartbeat : chaque jour à 20h daily investment deep dive, portfolio daily briefing, macro briefing. ⏱ 22:53

          
Computer use mobile
Via Dispatch, demander un fichier ou un screenshot. L'agent utilise littéralement le computer pour chercher, ouvrir, capturer et renvoyer. ⏱ 23:07

        

        
Quand choisir Cowork ?
Si vous débutez, voulez une option plus safe, moins de code, et acceptez moins de customisation. Le transcript l'utilise en parallèle d'OpenClaw pour différents use cases. ⏱ 24:11

Anti-patterns

        

          
1. Agent sur machine principale
Toutes vos données accessibles. Risque élevé si guardrails absents.

          
2. Installer des skills publiques sans audit
Le transcript mentionne security risk / scam via ClawHub.

          
3. Demander cinq features à la fois
Impossible de debugger. Une workflow à la fois.

          
4. Oublier la mémoire
Sans fichiers de contexte, l'agent n'est pas personnalisé et ne capitalise pas.

          
5. Pas de heartbeat
Reste réactif. Les vrais gains viennent des tâches schedulées.

          
6. Surestimer un vieux laptop 16GB
Petit modèle ou cloud. Gros open-source exige RAM.

          
7. Computer use sans supervision
L'agent peut bouger souris et écran. Human review nécessaire.

          
8. Croire qu'un seul agent suffit
Teams et parallel tasks peuvent être supérieures, mais design plus complexe.
